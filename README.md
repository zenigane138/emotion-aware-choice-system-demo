# 感情知覚型選択肢システム デモ

このリポジトリは、記事「選択肢の“重さ”をキャラクター感情から受け取る ― 感情知覚型選択肢システム」で紹介している考え方を、簡易的に確認するための動作サンプルです。

## 概要

このデモは、ビジュアルノベル等における選択肢入力を、単なる「分岐を決める操作」ではなく、キャラクターの心理抵抗・迷い・躊躇・衝動をプレイヤーに知覚させるための表現手段として扱う試作です。

本デモでは、選択肢の決定に長押し入力を用いています。

ただし、重要なのは「長押しそのもの」ではありません。

このデモの目的は、以下の感覚を確認することです。

- 選択肢を押し続ける時間が、心理的な抵抗として感じられるか
- 選択肢ごとの入力時間差が、キャラクターの迷い・躊躇として受け取れるか
- 決定途中に別の選択肢が現れることで、感情の揺らぎを表現できるか
- 短い入力時間でも、感情が弱いとは限らないことを示せるか

## このデモで確認したいこと

このデモでは、以下のような選択肢表現を試しています。

### 心理抵抗の違い

同じ「声をかける」行為でも、

- 名前を呼んで声をかける
- ただ声をかける
- 何もしない

では、キャラクターにとっての心理抵抗が異なる場合があります。

本デモでは、その違いを長押し時間や画面演出によって表現しています。

### 決断途中の感情変化

一部の選択肢では、押し続けている途中で新しい選択肢が現れます。

これは、選択前に分岐を提示するためではなく、決断しようとしている途中に別の言葉や逃げ道が浮かぶ感覚を表現するためのものです。

例:

- 聞こうとしていた言葉を飲み込む
- 笑ってごまかす
- 別の言葉に逃げる

### 衝動的な選択肢

本デモでは、終盤に「衝動的に呼び止める」という、極端に短い長押し時間の選択肢を用意しています。

これは「感情が弱いから短い」という意味ではありません。

このシステムにおいて、長押し時間が表しているのは感情の強さそのものではなく、その行動に対する心理抵抗や躊躇です。

そのため、

- 感情が強くても、抵抗や迷いが大きければ長くなる
- 感情が強くても、衝動的にあふれ出す行動であれば短くなる

という場合があります。

「長押し時間 = 感情量」ではなく、「長押し時間 = 心理抵抗」という考え方を確認するための例として配置しています。

## 操作方法

PCはマウス操作のみでキーボード操作には対応していません。
スマートフォンでも動作しない事はないのですが、PCを推奨します。

### テキスト送り

画面の案内に従ってクリックまたはタップしてください。

### 選択肢

選択肢は長押しで決定します。

押している途中で指やマウスボタンを離すとキャンセルされます。

## 注意事項

このデモは、記事内で述べている考え方を触って確認するための簡易サンプルです。

効果を検証するためのユーザーテストではありません。

また、体感差を分かりやすくするため、長押し時間はデモ用にかなり長めに設定しています。実際のゲームに組み込む場合は、作品のテンポ、シナリオ文脈、選択肢の頻度に合わせて調整が必要です。

## 実装上の考え方

このデモでは、選択肢ごとに主に以下の値を持たせています。

- `duration`: 長押しに必要な時間
- `load`: 画面演出に反映する心理的負荷の強さ
- `next`: 選択後の遷移先
- `reveals`: 長押し途中で追加表示される選択肢

`duration` と `load` を分けている点が重要です。

長押し時間が長いからといって、必ずしも演出負荷が最大になるとは限りません。

逆に、長押し時間が短くても、衝動や感情の爆発として強い演出を与えることもできます。

つまり、このデモでは以下のような表現を分けて扱うことを意図しています。

- 長くて重い選択
- 長いが静かな選択
- 短いが強い選択
- 短くて軽い選択

## 本デモの設計意図

このデモは、選択肢の「結果の重要性」を表現するものではありません。

重要なのは、キャラクター本人がその行動をどう感じているかです。

たとえば、物語上は重要な選択でも、キャラクター本人にとって自然な行動であれば入力は軽くなるかもしれません。

逆に、物語上は些細な言葉でも、キャラクターにとって強い心理抵抗があるなら、入力は重くなるかもしれません。

このデモは、そのような「キャラクター主観の重さ」を、選択肢入力そのものに乗せられるかを試すためのものです。

## QTEとの違い

このデモは、QTEのように反応速度や正確性を求めるものではありません。

多くのQTEでは、

- 制限時間内に入力する
- 正しいボタンを押す
- 失敗条件がある
- プレイヤーの反射や操作精度を試す

といった要素が中心になります。

一方、このデモで扱っている長押し入力は、プレイヤーの反射速度を試すためのものではありません。

目的は、キャラクターがその行動に至るまでの心理抵抗や迷いを、選択前の入力体験として知覚させることです。

## 長押し時間について

長押し時間は、それ単体では意味を持ちません。

プレイヤーがそれをキャラクターの心理抵抗として受け取るには、以下の要素が必要になります。

- シナリオ上の文脈
- 選択肢の文言
- UIフィードバック
- 画面演出
- 繰り返しによる学習
- 作品内での一貫性

そのため、実際のゲームでは、0.1秒単位で細かく調整するよりも、いくつかの段階に分けて設計する方が扱いやすいと考えています。

## 想定していない用途

このデモは、以下の目的には向いていません。

- アクセシビリティ対応の完成例として見ること
- 製品版UIの完成形として見ること
- 長押し時間の最適値を示すサンプルとして見ること
- この方式の有効性を証明する検証データとして扱うこと

あくまで、感情知覚型選択肢システムの考え方を体験するための試作です。
